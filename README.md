# JavaPlay — план проекта

Рабочее название игры: **JavaPlay: Хранители Ядра**.

2D-приключение, в котором игрок изучает Java, восстанавливая мир с помощью кода.
Реализована первая часть **M0**: основа React/TypeScript, статичная сцена острова в Phaser и подключённый редактор Monaco. Пользовательская приёмка ожидается.

## Запуск

Нужны **Node.js 25.6.0** и **npm 11.8.0** — версии текущего рабочего окружения, зафиксированные для воспроизводимости. Если используешь nvm, выполни `nvm install` и `nvm use` в корне проекта. Версию npm можно проверить командой `npm --version`.

Из корня проекта:

```sh
npm ci
npm run dev
```

Открой самостоятельно [http://127.0.0.1:5173](http://127.0.0.1:5173). Сервер не открывает браузер автоматически и слушает только локальный адрес. Если порт занят, останови использующий его процесс; адрес не меняется автоматически. Для остановки сервера нажми Ctrl+C.

Ожидаемый результат: экран «Деревня Начала» со статичным островом и маяком. Кнопка «Открыть редактор» показывает редактируемый Java-пример с подсветкой и номерами строк. На M0 движения, квестов, запуска кода и сохранения ещё нет; изменения примера сбрасываются при закрытии панели.

## Разрешённые статические проверки

```sh
npm run typecheck
npm run lint
npm run build
```

`build` включает проверку типов и сборку Vite. Все команды обходятся без браузера и тестов. Результат сборки — `apps/web/dist/`. Для самостоятельного просмотра production-сборки выполни `npm run preview` и открой [http://127.0.0.1:4173](http://127.0.0.1:4173).

## Структура первой части

- `apps/web/src/app/` — экран приложения и открытие панели.
- `apps/web/src/game/` — создание/уничтожение Phaser и статичная сцена.
- `apps/web/src/features/editor/` — Monaco и локальный worker; CDN не используется.
- `apps/web/src/styles/` — токены оформления и адаптивная компоновка.
- `packages/contracts/` — общий тип событий жизненного цикла мира.
- Конфигурация в корне — npm workspaces, TypeScript, ESLint и lockfile.

## Текущие договорённости

- Работаем итерационно: сначала небольшой законченный игровой цикл, затем расширение.
- Агент не использует браузер для проверки. Игру проверяет и тестирует пользователь.
- Юнит-тесты сейчас не пишем; внедрение автотестов — отдельный будущий этап.
- Компиляция, проверка типов и линтер допустимы, когда появится код. Они не заменяют пользовательскую приёмку.
- Игровая проверка кода ученика входит в продукт; она не равнозначна юнит-тестам репозитория.
- Документы описывают решения и будущую работу, а не уже реализованные возможности.

Сейчас нужно вручную проверить **A0** из [сценариев приёмки](docs/05-manual-acceptance.md). Следующая часть после твоей приёмки — **M1**: герой, передвижение, коллизии и NPC.
