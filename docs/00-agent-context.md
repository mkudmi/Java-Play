# Контекст для агентов

Этот файл — первый короткий вход в проект после `AGENTS.md` и `README.md`.
Его цель: быстро показать, что уже сделано, что только запланировано и какие документы читать дальше под конкретную задачу.

## Быстрый статус

**Дата среза:** 2026-09-08.

**Текущий этап:** M1 реализован и проверен статически; ожидается ручная приёмка A1 пользователем.

**Следующая продуктовая часть:** M2 — диалоги, принятие Q01 и журнал текущей цели.

**Не начинать без явного указания или приёмки зависимости:** M3+ как зависимые функциональные этапы. Документационные и подготовительные изменения можно делать независимо, если они не заявляют будущую функциональность готовой.

**Ограничение проверки:** агент не открывает браузер, не запускает browser automation и не пишет тесты. Разрешены только статические проверки из `README.md`, если они нужны для изменения и не запускают тесты скрыто.

## Правила обновления контекста

Обновляй этот файл только когда меняется один из пунктов:

- статус этапа: запланировано, реализовано, проверено статически, ожидает приёмки, принято пользователем;
- следующий рекомендуемый шаг;
- существенная архитектурная граница или запрет;
- список готовых/неготовых областей;
- карта чтения, если появились новые важные документы или модули.

Не превращай файл в подробный changelog. Подробности реализации, проверки и замечания записывай в `docs/06-agent-worklog.md`; план этапов обновляй в `docs/04-implementation-plan.md`.

## Формат записи статуса

Используй точные формулировки:

- `запланировано` — описано, но не реализовано;
- `реализовано` — код или документ изменён;
- `проверено статически` — выполнена разрешённая команда и указан результат;
- `ожидает ручной приёмки` — пользователю переданы сценарии, но подтверждения нет;
- `принято пользователем` — пользователь явно подтвердил сценарий или ограничение.

Не используй `готово`, если не ясно, означает ли это реализацию, статическую проверку или пользовательскую приёмку.
