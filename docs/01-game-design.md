# Game Design Document

Статус: исходный проектный документ, до реализации. Дата: 2026-09-08.

## 1. Название и концепция

Пять вариантов названия:

| Название | Акцент |
|---|---|
| JavaPlay: Хранители Ядра | Прямая связь Java и приключения; рабочий вариант |
| Codebound: Архипелаг Java | Исследование взаимосвязанного мира |
| Ядро: Язык миров | Сюжет о восстановлении систем |
| Java Quest: Город механизмов | Практические квесты и инженерия |
| Байткод: Путь архитектора | Профессиональное развитие героя |

Рабочее название не означает проверку торговой марки или доступности домена.

Игрок — ученик Хранителей, способный менять поведение механизмов через Java. Он исследует top-down мир, разговаривает с NPC, пишет код, видит последствия и постепенно получает более самостоятельные инженерные задачи.

Аудитория: от 10–12 лет до взрослых новичков и продолжающих. Основной язык — русский, ключевые слова Java и оригинальные сообщения компилятора сохраняются. Сложность определяется освоенными навыками, а не возрастом.

## 2. Сюжет, герой и NPC

Архипелаг Логос жил благодаря Ядру — системе договоров между городами, транспортом и мастерскими. После «Великого исправления» автономные механизмы продолжают выполнять старые инструкции, но перестали понимать друг друга. Единого злодея нет: неполные требования, неверные предположения и поспешные исправления породили цепочку сбоев.

Герой прибывает на последнем рабочем пароме. Его первый успех — восстановленный маяк; финальная ответственность — надёжная система городских сервисов. Между этими точками он проходит путь от изменения одной строки до проектирования взаимодействующих программ. У героя настраиваемые имя и внешний вид; скорость реакции и бой не блокируют обучение.

| NPC | Характер и роль | Пример короткой реплики |
|---|---|---|
| Ира, хранительница маяка | Спокойный наставник; основы | «Сначала попросим маяк подать один сигнал». |
| Бор, инженер | Практик; алгоритмы и механизмы | «Вручную я это уже сделал. Семь раз. Хватит». |
| Ника, багхантер | Наблюдательная; отладка | «Ошибка полезная. Она хотя бы оставила адрес». |
| Север, архитектор | Требовательный, без высокомерия; ООП и backend | «Кто отвечает за покупку, если склад недоступен?» |
| Рэй, исследователь | Любопытный; JVM, конкурентность, профилирование | «Два робота быстрые. Теперь научим их не спорить за один ящик». |

NPC дают короткие диалоги по 1–3 фразы. Дополнительные объяснения открываются по желанию. У каждого есть собственная проблема, чтобы квесты не выглядели выдачей учебных упражнений.

## 3. Мир и карта

Регионы — узлы связанной карты, а не бесконечный открытый мир. Внутри них небольшие исследуемые сцены, терминалы, секреты и механизмы.

Основной маршрут: **Деревня Начала → Долина Переменных → Перекрёсток Решений → Лес Циклов → Архипелаг Массивов → Город Методов → Королевство Объектов → Торговая Лига коллекций → Академия Обобщений → Река Потоков → Фабрика Параллелей → Подземелья JVM → Столица Сервисов**.

Боковые учебные ветки: **Мастерская Строк**, **Служба Спасения** (исключения), **Архив Файлов**, **Порт Инструментов**. У них явные зависимости в карте курса; географическая близость не означает доступность без нужных знаний.

В каждой территории есть локальная проблема, новая возможность героя, несколько видов практики, повторение старых тем, босс и мини-проект. Восстановленные места меняются: появляется свет, ходит транспорт, открываются мастерские. Старые регионы дают новые задачи, требующие более зрелых решений.

## 4. Основной игровой цикл

1. Исследовать сцену и заметить проблему.
2. Подойти к NPC или терминалу, взаимодействовать.
3. Получить контекст и короткое объяснение нового понятия.
4. Посмотреть пример и выполнить малую практику.
5. Самостоятельно изменить или написать Java-код.
6. Нажать «Запустить», прочитать вывод или ошибку.
7. Увидеть действия механизма в мире.
8. Проверить цель, получить обратную связь и при необходимости исправить код.
9. Получить награду и открыть следующий квест.
10. Позже применить это знание в другом контексте без готового шаблона.

Успех — достижение цели задачи, а не совпадение текста с образцом. Проверка допускает разные корректные решения. Если цель требует конкретной конструкции, ограничение явно объясняется и проверяется структурно; поиск подстроки в коде непригоден.

## 5. Code → World

Учебный API предоставляет ограниченные команды: `beacon.signal(...)`, `door.open()`, `robot.move(...)`, `robot.collect(...)`. Каждая команда относится к доступному механизму и имеет понятное действие в сцене.

Например, после изучения циклов:

```java
for (int i = 0; i < 5; i++) {
    robot.move(1);
}
```

Исполнитель формирует пять ограниченных событий движения; мир воспроизводит их по порядку. Учебный API вводится в уроке: игрок не должен угадывать скрытые методы. Карта показывает препятствия и исходное положение.

«Запустить» воспроизводит результат в состоянии попытки. «Проверить» оценивает условия задания. Постоянные изменения и награды фиксируются только после успеха. При ошибке попытка сбрасывается к снимку; уже заработанные награды не теряются. Это позволяет экспериментировать без повреждения сохранения.

В профессиональных главах действие мира зависит от ответов API и состояния учебной БД: отказ магазина виден как закрытая лавка, ошибочная транзакция — как несовпадение оплаты и выдачи предмета. Это отдельная версия продукта с другим исполнителем, не расширение синтаксического симулятора.

## 6. Прогрессия, XP и достижения

- Малое упражнение: 10 XP; сюжетный квест: 30 XP; босс: 100 XP; мини-проект: 150 XP. Это начальные параметры для балансировки.
- Каждая награда выдаётся один раз по стабильному ID завершения. Повторное прохождение даёт практику, но не бесконечный XP.
- Начальные уровни требуют по 100 XP; позже кривая уточняется по пользовательской обратной связи.
- Уровень открывает косметику и оформление мастерской. Новые знания открываются по prerequisites и самостоятельным решениям, а не по накопленному XP.
- Skill Tree показывает состояния: закрыто, доступно, изучается, применено самостоятельно, пора повторить.
- Инвентарь хранит сюжетные предметы, инструменты и коллекционные заметки. Косметика не влияет на доступ к знаниям.
- Достижения: «Hello World», «Без костылей», «Охотник на баги» (50 исправленных задач), «Цикломания» (100 разных успешных задач с циклами), «NullPointer Survivor», «Договор дороже кода», «Два робота — один билет», скрытое «Он всё ещё идёт» за обнаружение зацикленного NPC.
- Подсказки не уменьшают базовую награду. Решение без подсказок влияет на отдельное достижение и оценку самостоятельности.

Статистика показывает освоенные навыки, время практики и темы повторения. Нет наказания за пропущенный день и публичного рейтинга скорости обучения.

## 7. Подсказки и адаптация

Три уровня, открываемые игроком: намёк → направление → почти готовое решение. Для сложных понятий доступны «Объяснить проще» и «Разобраться глубже». После третьей подсказки предлагается похожая самостоятельная задача, чтобы отличать узнавание решения от навыка.

Исходная адаптация детерминированная: три содержательные неудачи по одной теме предлагают упрощённую практику; два самостоятельных успеха в разных контекстах позволяют перейти к усложнённой задаче. Инфраструктурные ошибки и повторы одной отправки не учитываются. Игрок вправе отказаться от дополнительной практики; контрольная задача сохраняется.

Повторение предлагается через 1, 3, 7 и 14 дней после подтверждённого освоения; ошибка возвращает короткий интервал. Это стартовая настройка, не утверждение об универсально оптимальной методике. Старые темы также включаются в новые квесты независимо от календаря.

## 8. UI/UX и визуальный стиль

Основной экран — мир с небольшими HUD: текущая цель, XP, журнал, карта. WASD/стрелки — движение, E — взаимодействие, Escape — закрыть панель. При фокусе редактора игровые клавиши отключены. В MVP основной сценарий — desktop с клавиатурой; полноценное мобильное управление позже.

Панель терминала: слева проблема, NPC и краткое объяснение; справа Monaco; снизу «Запустить», «Проверить», «Подсказка», «Сбросить», вкладки вывода и ошибок. Сброс кода требует подтверждения, если есть правки; закрытие панели сохраняет черновик. Во время выполнения показаны статус и отмена, повторная отправка блокируется.

Редактор: подсветка Java, номера строк, автоскобки, ограниченные подсказки имён доступного API, выделение строки ошибки. Подсказки не вставляют решение. Языковой сервер и полноценный IDE-autocomplete — отдельное расширение; не считать их автоматически доступными в Monaco.

Оригинальная ошибка доступна всегда; русское пояснение показывает смысл и следующий шаг. Позиции ошибок отображаются относительно видимого кода, а не скрытой обёртки. При сбое исполнителя отдельно сообщается, что решение не оценивалось.

Стиль — clean 2D top-down с чёткими силуэтами, мягким освещением и небольшими анимациями. Он позволяет получить цельный MVP без большого набора уникального pixel art. Регионы отличаются палитрой и устройствами. Шрифт кода не пиксельный; масштаб текста регулируется. Важные состояния обозначаются и текстом, и формой; анимации можно сократить, звук отключить. Drag & Drop позднее имеет клавиатурную альтернативу.

## 9. Границы MVP

Одна небольшая сцена Деревни Начала, герой, коллизии, два NPC, терминал, маяк и ворота. Пять последовательных квестов: вывод → переменная → арифметика → исправление ошибки → самостоятельное восстановление маяка. Детализация — в плане реализации.

Обязательны: настоящий маршрут по сцене, диалог, редактор, ограниченный явно обозначенный симулятор, полезная ошибка, изменение мира от кода, проверка цели, однократный XP, сохранение и следующий квест. Стартовый босс и мини-проект совмещены в последнем квесте.

В MVP не входят: полный курс, аккаунты, серверная БД, удалённая JVM, multiplayer, мобильный интерфейс, генерация заданий ИИ, расширенная адаптация, ежедневные активности, полноценный магазин косметики. Базовое дерево навыков и одно достижение входят; остальные системы получают расширение после работающего цикла.

Почему так: сначала нужно подтвердить, что программирование ощущается действием в мире и новичок понимает обратную связь. Количество территорий само по себе этого не доказывает.
