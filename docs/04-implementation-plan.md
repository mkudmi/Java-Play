# План реализации

## Статус и порядок работы

**M0 реализован, ожидает пользовательской приёмки.** Остальные этапы запланированы. Разработка идёт последовательно, по одной части.

Последовательность MVP: **M0 → M1 → M2 → M3 → M4 → M5 → M6 → M7**.
Оценки сроков пока не фиксируются: сначала нужна обратная связь по первому сквозному циклу. Размер этапа определяется наблюдаемым результатом, а не числом файлов.

Агент выполняет только разрешённые статические проверки. Браузер, игровое тестирование и ручная приёмка — пользователь. Автотесты репозитория, включая юнит-тесты, отложены; отдельная строка в будущем backlog не является разрешением написать их сейчас.

## MVP: этапы и критерии выхода

### M0. Основа проекта и фиксированные решения

**Статус на 2026-09-08:** реализовано и проверено статически. Пользовательская приёмка A0 ещё не проведена.

**Цель:** воспроизводимая основа для последующих изменений.

- Создать TypeScript/React/Vite-приложение и минимальные workspace packages по архитектуре.
- Зафиксировать версии Node, package manager и зависимостей в конфигурации и lockfile.
- Подключить Phaser и Monaco без реализации всех панелей сразу.
- Настроить сборку, typecheck и lint без test runner и без браузерных проверок.
- Создать цветовые/типографические токены, базовый layout и README запуска.
- Записать принятые версии и структуру в архитектурный документ.

**Результат:** приложение запускается локально, показывает базовую сцену и место учебной панели. Агент подтверждает только сборку/типизацию; пользователь проверяет запуск по A0.

Созданы `apps/web` и используемый пакет `packages/contracts`. `content-schema` и `simulator` появятся соответственно на M2 и M3: пустые пакеты заранее не создавались. Monaco открывается по кнопке, Java-пример редактируется без выполнения. Сцена нарисована средствами Phaser, внешние изображения и шрифты не требуются. Передвижение не входит в M0.

**Проверки M0:** `npm ci`, `npm run typecheck`, `npm run lint` и `npm run build` завершились успешно; аудит при чистой установке сообщает 0 известных уязвимостей. Браузер и автоматические тесты не запускались. Vite предупреждает о крупных чанках Phaser (~1,21 MB) и Monaco (~2,65 MB) до gzip; оба выделены динамическими импортами, Monaco загружается при открытии панели. Предупреждение оставлено видимым, дальнейшая оптимизация — после функциональных этапов и обратной связи пользователя.

### M1. Исследуемый мир

**Зависимость:** принятый M0.

- Создать одну карту Деревни Начала с берегом, маяком, воротами и мастерской.
- Добавить героя, движение, камеру, коллизии и простую анимацию.
- Добавить NPC Иру и Нику, зоны взаимодействия и подсказку клавиши.
- Сделать единый источник ввода; остановку движения при открытии панели.

**Результат:** пользователь ходит по сцене и подходит к NPC; стены и вода ограничивают движение. Приёмка A1. Пока не выдавать сцену за готовый MVP.

### M2. Диалог и жизненный цикл квеста

**Зависимость:** M1.

- Реализовать короткие диалоги, журнал текущей цели, принятие квеста и prerequisites.
- Создать схемы контента и первый квест Q01.
- Обрабатывать повторное взаимодействие: NPC знает, принят ли квест, но пока не выдаёт награду.
- Добавить видимые состояния закрытого/доступного/активного задания.

**Результат:** от NPC можно получить задачу и открыть описание без ручной навигации по учебнику. Приёмка A2.

### M3. Редактор и ограниченный исполнитель

**Зависимость:** M2; контракт ExecutionProvider фиксируется перед реализацией.

- Встроить Monaco, starter code, stdout и диагностику с координатами.
- Реализовать tokenizer, AST и evaluator только подмножества из архитектуры.
- Выполнять код в Worker; добавить лимиты, отмену и защиту от устаревших ответов.
- Реализовать Run, сброс с подтверждением, сохранение черновика в памяти и три подсказки.
- Явно показывать режим симулятора и понятное сообщение для неподдержанного синтаксиса.

**Результат:** код Q01 вычисляется, изменённые значения меняют вывод; неверный код даёт диагностируемую ошибку. Приёмка A3. Здесь нет настоящего javac и нельзя утверждать обратное.

### M4. Первый завершённый Code → World цикл

**Зависимость:** M3.

- Реализовать события от выполнения, состояние попытки и воспроизведение мира.
- Добавить evaluator Q01, кнопку проверки и понятный результат.
- При успехе включать маяк, завершать квест, начислять XP один раз и открывать следующий.
- Реализовать достижение «Hello World» и минимальное отображение прогресса.
- Не позволять ошибке/отмене/повтору результата повторно менять постоянное состояние.

**Результат:** герой → NPC → объяснение → код → Run → проверка → изменение мира → XP → следующий квест. Приёмка A4. Это первая функциональная вертикаль, но ещё не весь MVP.

### M5. Полная стартовая цепочка

**Зависимость:** M4.

| ID | Квест | Учебная цель | Условие завершения и эффект |
|---|---|---|---|
| Q01 | «Сигнал с берега» | println в готовом main | Ожидаемое сообщение в stdout; загорается сигнальная лампа; 30 XP |
| Q02 | «Запас энергии» | Объявление int и чтение переменной | Значение заряда вычислено и передано в beacon.signal; индикатор заполнен; 30 XP |
| Q03 | «Цена маршрута» | Вычитание и умножение | Из стартового топлива вычтен расход на путь, остаток передан механизму; включается дорожка; 30 XP |
| Q04 | «Чужое имя» | Чтение диагностики и исправление идентификатора | Переменная исправлена, вычисление успешно; ремонтная платформа работает; 30 XP |
| Q05 | «Запуск большого маяка» | Самостоятельное сочетание вывода, переменных и арифметики | По условию рассчитана энергия, механизм запущен и напечатан отчёт; ворота открыты; 100 XP за босса + 150 XP за мини-проект |

- Для каждого квеста написать карточку по методике, три подсказки и короткие реплики NPC.
- Не требовать условий/циклов/ООП в Q05. Дать учебный API и техническую цель, не готовую формулу решения.
- Чередовать заполнение, предсказание, исправление и самостоятельное написание.
- Добавить минимальное дерево навыков: вывод → переменные → арифметика → самостоятельное применение.

**Результат:** пять связанных квестов, заметное восстановление сцены и завершение главы. Приёмка A5. Босс и мини-проект здесь одно задание; обе награды фиксируются один раз по разным типам ledger.

### M6. Сохранение и восстановление

**Зависимость:** M5.

- Добавить IndexedDB, версию схемы, миграционный интерфейс, атомарное сохранение завершения и награды.
- Сохранять прогресс, положение, изменения мира, достижения, подсказки и черновики.
- Реализовать экспорт/импорт с валидацией, обработку повреждённого/несовместимого сохранения и сброс с подтверждением.
- При reload восстанавливать согласованное состояние без повторного начисления наград.

**Результат:** прохождение продолжается с сохранённого места; проблемы хранения не скрываются. Приёмка A6.

### M7. Подготовка MVP к пользовательской приёмке

**Зависимость:** M6.

- Доработать читаемость, фокус, состояния загрузки/ошибок, размеры панели и отключение анимаций.
- Обновить инструкции запуска и список известных ограничений.
- Выполнить доступные сборку, typecheck и lint; не запускать браузер или тесты.
- Передать пользователю полный сценарий A0–A7, собрать замечания и исправить дефекты в пределах MVP.

**Результат:** пользователь подтвердил полный цикл и сохранение, блокирующие дефекты устранены либо он явно принял ограничение. До его ответа статус — «готово к ручной проверке», а не «принято».

## Отложенные задачи

- **Автотесты репозитория — только по отдельному запросу.** Начать позже с parser/evaluator, идемпотентных наград, переходов квеста и миграций; не создавать файлы сейчас.
- Backend-учебные тесты JUnit/Mockito/Testcontainers входят в поздний курс и не отменяют текущую договорённость.
- Multiplayer, мобильный интерфейс, пользовательский редактор уровней, облачные слоты сохранений, расширенная косметика, локализации и ИИ-наставник — вне базового маршрута до отдельной приоритизации.

## Основные риски и решения

| Риск | Решение |
|---|---|
| Слишком большой курс до первого результата | Сначала M4, затем пять квестов, затем расширение |
| Симулятор закрепляет неверный Java | Узкая грамматика, явная маркировка, переход к JVM до сложных тем |
| Редактор превращает игру в учебник | Каждый квест меняет механизм/сцену, движение и NPC входят в MVP |
| Потеря прогресса/двойная награда | Версии данных, атомарная запись, уникальные завершения |
| Небезопасное исполнение | Отдельный sandbox worker, лимиты, запрет публичного запуска до защит |
| Иллюзия знания после подсказок | Самостоятельная задача в другом контексте и мини-проект |
| Проверка результата требует пользователя | Маленькие этапы и точные сценарии приёмки; статус не завышать |

## Как обновлять этот план

После реализации этапа записать дату, изменённые области, выполненные статические проверки и известные ограничения. После ответа пользователя отдельно записать результат приёмки и его замечания. Не ставить галочку за будущую функциональность на основании того, что её структура уже создана.
