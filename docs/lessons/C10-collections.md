# C10. Торговая Лига — Collections

## Роль региона

Игрок переходит от фиксированных массивов к структурам стандартной библиотеки. Главная цель — выбирать коллекцию по свойствам задачи, а не по привычке.

## Prerequisites

C07. Простая запись generics читается здесь, глубокая тема вынесена в C11.

## Последовательность уроков

| ID | Урок | Новая идея | Практика | Эффект мира |
|---|---|---|---|---|
| C10-L01 | `List` | Упорядоченный изменяемый список | Добавлять товары | Полка растёт |
| C10-L02 | `ArrayList` и `LinkedList` | Разная стоимость операций | Выбрать список под сценарий | Торговец объясняет компромисс |
| C10-L03 | `Set` | Уникальность | Убрать дубликаты пропусков | Ворота перестают спорить |
| C10-L04 | `HashSet` и `TreeSet` | Хеширование и порядок | Сравнить поиск и сортировку | Реестр работает по правилу |
| C10-L05 | `Map` | Ключ → значение | Найти товар по ID | Склад отвечает мгновенно |
| C10-L06 | `Queue` и `Deque` | Очередь задач | Обработать поставки | Роботы берут задания по порядку |
| C10-L07 | Iterator | Безопасный обход с удалением | Удалить просроченные записи | Архив не падает |
| C10-L08 | Comparator/Comparable | Порядок сортировки | Отсортировать заказы | Таблица становится читаемой |
| C10-L09 | Stack в legacy | Читать старый код через Deque | Заменить рекомендацию | Старый механизм документирован |

## Обязательные понятия

Интерфейсы коллекций, реализации, размер, добавление, удаление, поиск, уникальность, ключ, порядок, iterator, comparator, Big O на интуитивном уровне.

## Границы

Не углубляться в PECS и bounded wildcards до C11. Не показывать `Stack` как основной современный выбор.

## Игровые квесты

- Наладить склад товаров.
- Убрать дубликаты пропусков.
- Сделать быстрый поиск заказа по ID.

## Проверяемые навыки

Игрок может обосновать выбор `List`, `Set`, `Map` или `Queue` через требования: порядок, уникальность, поиск, частота вставок и удалений.
