# C11. Академия Обобщений — Generics

## Роль региона

Игрок учится писать компоненты, которые работают с разными типами и сохраняют типовую безопасность на этапе компиляции.

## Prerequisites

C10: коллекции и базовое чтение `List<Item>`.

## Последовательность уроков

| ID | Урок | Новая идея | Практика | Эффект мира |
|---|---|---|---|---|
| C11-L01 | Зачем generics | Типобезопасный контейнер | Создать `Box<T>` | Контейнер хранит только нужный груз |
| C11-L02 | Generic methods | Тип параметризуется методом | Написать `first(List<T>)` | Диспетчер берёт первый элемент |
| C11-L03 | Bounds | Ограничение типа | Принимать только `Cargo` | Склад не принимает случайные объекты |
| C11-L04 | Wildcards | Неизвестный подтип | Читать из списка разных грузов | Инспектор считает общий вес |
| C11-L05 | PECS | Producer extends, consumer super | Переложить грузы безопасно | Портовые контейнеры совместимы |
| C11-L06 | Type erasure | Ограничения во время выполнения | Разобрать невозможную проверку | Академия показывает границу JVM |

## Обязательные понятия

Параметр типа, generic class, generic method, bounded type, wildcard, `extends`, `super`, PECS, type erasure, raw type как legacy-опасность.

## Границы

Не начинать с сложных сигнатур. Каждый wildcard должен появляться из проблемы чтения или записи, иначе он выглядит магией.

## Игровые квесты

- Сделать типизированное хранилище грузов.
- Исправить raw type, который допускает неверный предмет.
- Переносить грузы между контейнерами с PECS.

## Проверяемые навыки

Игрок может объяснить, почему ошибка типов лучше на компиляции, и выбрать `extends` для источника, `super` для приёмника.
