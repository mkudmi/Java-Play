# C14. Фабрика Параллелей — Multithreading & Concurrency

## Роль региона

Игрок впервые сталкивается с несколькими работниками, которые выполняют код одновременно. Цель — понять риски общего состояния, а не просто создать много потоков.

## Prerequisites

C09, C11, C13: исключения, generics, functional Java.

## Последовательность уроков

| ID | Урок | Новая идея | Практика | Эффект мира |
|---|---|---|---|---|
| C14-L01 | Thread и Runnable | Отдельный поток выполнения | Запустить фонового робота | Доставка идёт параллельно |
| C14-L02 | Lifecycle | Состояния потока | Проследить start/run/join | Панель показывает этапы |
| C14-L03 | Race condition | Общие данные ломаются | Продать последний билет двумя роботами | Ошибка становится видимой |
| C14-L04 | `synchronized` | Критическая секция | Защитить продажу | Продаётся один билет |
| C14-L05 | `volatile` | Видимость, не атомарность | Остановить worker-флагом | Рэй объясняет границу |
| C14-L06 | Locks и atomics | Более точные инструменты | Заменить счётчик на `AtomicInteger` | Счётчик совпадает |
| C14-L07 | ExecutorService | Управление задачами | Отправить партии доставок | Фабрика не создаёт потоки вручную |
| C14-L08 | Future и CompletableFuture | Результат позже | Объединить ответы станций | Карта ждёт несколько сигналов |
| C14-L09 | Concurrent collections | Коллекции для конкуренции | Общая очередь задач | Роботы не теряют задания |
| C14-L10 | Virtual threads | Много лёгких задач при поддержке JDK | Сравнить сценарий IO | Учебный стенд показывает ограничение версии |

## Обязательные понятия

Поток, задача, lifecycle, join, race condition, shared mutable state, critical section, visibility, atomicity, synchronized, lock, atomic, executor, future, concurrent collections.

## Границы

Не говорить, что `volatile` заменяет атомарность. Virtual threads вводить только при зафиксированном поддерживаемом JDK и с объяснением области применения.

## Игровые квесты

- Расследовать двойную продажу одного предмета.
- Синхронизировать доступ к складу.
- Собрать диспетчер доставки через executor.

## Проверяемые навыки

Игрок может воспроизвести гонку в управляемом сценарии, объяснить причину и выбрать простой механизм защиты общего состояния.
