# Acts, Progression, Finale

## Complete Story Acts

| Act | Chapters | Educational Focus | Story Function | Scale |
|---|---|---|---|---|
| ACT I — Discovery | C01 | Computer & Java Zero | Герой впервые видит, что код меняет мир. | Предмет, комната, маяк |
| ACT II — Control | C02-C06 | Variables, conditions, loops, arrays, methods | Игрок управляет состоянием, выбором, повторением, группами и декомпозицией. | Поселение и малые системы |
| ACT III — Structure | C07-C11 | OOP, strings, exceptions, collections, generics | Мир раскрывается как сеть объектов, договоров и типов. | Регион |
| ACT IV — Memory And Failure | C12-C16 | Files, streams of data, concurrency, JVM, tools | Игрок расследует долговременные данные, одновременность и исполнение. | Городские узлы |
| ACT V — Connection | C17-C19 | HTTP, databases, Spring | Локальные решения связываются в backend-систему городов. | Сеть городов |
| ACT VI — Architect | C20 | Professional Java | Финальный релиз новой архитектуры. | Весь архипелаг |

## Main Quest Progression

1. Герой прибывает в Светлицу и восстанавливает первый сигнал.
2. Локальный ремонт показывает, что сбои повторяются в разных устройствах.
3. Игрок учится описывать состояние, правила, повторения и группы, чтобы вернуть работу поселению.
4. ООП раскрывает: устройства не отдельные загадки, а экземпляры типов с контрактами.
5. Ошибки, строки, коллекции и generics показывают, что инфраструктура сломалась из-за слабых границ данных и договоров.
6. Файлы, Stream API, concurrency и JVM открывают следы Великого Исправления.
7. Инструменты разработчика выводят игрока из учебного редактора к настоящим проектам.
8. HTTP, SQL и Spring превращают ремонт в создание сервисов.
9. Финал требует архитектуры, безопасности, тестирования как учебной темы, Docker, наблюдаемости и документации.

## Final Act

Финальная арка начинается с честного признания: Куратор нельзя просто отключить. Он держит часть инфраструктуры в рабочем состоянии, а старые ручные процессы уже не выдержат нагрузку. Игрок получает карту зависимостей, журналы инцидентов, неполную документацию, конфликтующие требования Совета и реальные ограничения жителей.

Финал состоит из нескольких связанных этапов:

- прочитать legacy-код и определить, где поведение нельзя менять без миграции;
- выделить доменные сущности, права и границы сервисов;
- спроектировать REST API для магазина, склада и транспорта;
- восстановить SQL-схему, ключи, индексы и транзакции;
- внедрить Spring Boot слои: controller, service, repository, configuration, exception handling;
- учесть конкурентный сценарий ограниченного ресурса;
- добавить проверку входных данных, auth/authz и понятные ошибки;
- подготовить учебные тесты как доказательство поведения в C20;
- собрать Docker-окружение и инструкции запуска;
- провести финальный review с Севером, Никой, Марой, Бором и Рэем.

## Final Educational Project As Story Finale

Финальный проект — backend города, от которого физически зависит мир. После запуска новой системы витрина показывает реальные товары, склад не расходится с оплатой, транспорт получает подтвержденные задания, жители видят статус заявок, а Куратор переводится из автономного правщика в ограниченный диагностический сервис. Обучение и развязка совпадают: игрок выпускает систему, которая решает глобальный конфликт.

## Epilogue

В эпилоге Светлица больше не край мира, а учебная станция для новичков. Ира ведет первые занятия, Бор сопровождает полевые ремонты, Ника разбирает инциденты публично и спокойно, Рэй поддерживает стенд JVM, Мара представляет жителей в совете, Таль отправляет игроку первый нормальный pull request без комментария "потом поправим".

Старые системы игрока остаются видимыми: маяк, калькулятор маршрутов, диспетчер ворот, склад, архив, сервис заказов. Некоторые ранние решения можно открыть в режиме "legacy memory" и увидеть, как выросло мышление героя.
