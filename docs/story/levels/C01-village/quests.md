# CHAPTER 01 Quest Pack — Последний паром

Статус: проектный контент для будущей реализации. Это не runtime-данные игры и не готовая техническая схема.

## Design Goal

Собрать первый учебно-сюжетный цикл так, чтобы игрок без знаний программирования понял: Java-код в этом мире является точной инструкцией для станции Ядра, а не отдельным уроком в меню. Все квесты происходят в Светлице вокруг причала, маяка, журнала сигналов и учебного контура станции.

## Quest C01-Q01 — Лестница к фонарю

### Метаданные

- ID: C01-Q01
- Версия: 0.1.0
- Регион: Светлица
- Название: Лестница к фонарю
- Главная тема: программа как точная последовательность инструкций
- Prerequisites: нет
- Unlocks: C01-Q02
- Ориентир длительности: 5 минут
- Формат: объяснение + интерактивная практика

### Учебная цель

Игрок понимает, что компьютер или станция выполняет инструкции строго в указанном порядке и не додумывает намерение человека.

### Проблема мира

Линза маяка застряла после неправильной последовательности обслуживания: сначала попытались включить фонарь, потом повернуть линзу, потом снять защитный стопор.

### Диалог

Ира: "Маяк не упрямится. Он просто сделал ровно то, что ему сказали."

Ира: "Давай без кода для начала. Расставь действия так, чтобы механизм вообще мог начать слушать."

### Объяснение

- Простыми словами: программа — это список точных шагов.
- Аналогия: рецепт, где нельзя сначала поставить пирог в печь, а потом замесить тесто.
- Граница аналогии: программа строже рецепта; она не понимает "ну ты понял".
- Точная Java-модель: Java-программа позже будет таким же набором точных инструкций, только записанных текстом.

### Пример

```java
// Код появится позже. Сейчас игрок работает с порядком действий.
```

### Практика игрока

- Starter state: четыре карточки действий: "снять стопор", "повернуть линзу", "подать питание", "записать сигнал".
- Что разрешено менять: порядок карточек.
- Разрешенный API мира: нет.
- Что должно произойти после запуска: линза поворачивается, но фонарь еще не светит.

### Проверка

- Критерий успеха: действия идут в физически допустимом порядке.
- Допустимые варианты решения: один основной порядок; "записать сигнал" может стоять после подачи питания или быть последним, если механизм уже готов.
- Что проверять структурно: последовательность состояний механизма.
- Что не проверять поиском подстроки: ничего, Java-кода еще нет.
- Типичные ошибки: включить питание до снятия стопора, записать сигнал до готовности станции.

### Подсказки

1. Намек: "Что должно быть свободно, прежде чем оно повернется?"
2. Направление: "Сначала безопасность, потом движение, потом питание."
3. Почти готовое решение: "Сними стопор, поверни линзу, подай питание, затем запиши сигнал."

### Награда и перенос навыка

- XP: 10
- Изменение мира: линза встает в рабочее положение.
- Открываемые темы: исходный код.
- Где навык повторится позже: порядок методов в C06 и lifecycle потоков в C14.

## Quest C01-Q02 — Строка, которую читает станция

### Метаданные

- ID: C01-Q02
- Версия: 0.1.0
- Регион: Светлица
- Название: Строка, которую читает станция
- Главная тема: исходный код
- Prerequisites: C01-Q01
- Unlocks: C01-Q03
- Ориентир длительности: 5-7 минут
- Формат: малая практика в редакторе

### Учебная цель

Игрок понимает, что исходный код — это текст программы, который человек может читать и менять, а станция использует как инструкцию.

### Проблема мира

Панель маяка показывает устаревший сигнал "DOCK CLOSED", хотя причал свободен. Ира не просит "выучить синтаксис"; ей нужно, чтобы станция отправила правильную запись.

### Диалог

Ира: "Вот текст, который станция читает перед отправкой сигнала. Не весь маяк сломан. Одна строка говорит неправду."

Ника: "Хорошая новость: ошибка честно лежит на виду. Такое бывает реже, чем хотелось бы."

### Объяснение

- Простыми словами: исходный код — текст, который описывает поведение программы.
- Аналогия: инструкция на табличке для дежурного механизма.
- Граница аналогии: код проверяется строгими правилами языка, а не только здравым смыслом.
- Точная Java-модель: в `.java` файле находится исходный текст, который инструменты Java смогут обработать.

### Пример

```java
// Станция покажет этот текст на панели сигнала:
"DOCK OPEN"
```

### Практика игрока

- Starter code:

```java
// Signal text
"DOCK CLOSED"
```

- Что разрешено менять: только текст внутри кавычек.
- Разрешенный API мира: учебная панель `signal.previewText(...)` может быть скрытой оберткой продукта, но игрок ее не видит.
- Что должно произойти после запуска: панель маяка показывает `DOCK OPEN`.

### Проверка

- Критерий успеха: итоговое значение сигнала равно `DOCK OPEN`.
- Допустимые варианты решения: точная строка в кавычках.
- Что проверять структурно: наличие строкового литерала как результата редактируемой области.
- Что не проверять поиском подстроки: не засчитывать `// DOCK OPEN`, если рабочая строка не изменилась.
- Типичные ошибки: удалить кавычки, изменить комментарий вместо рабочей строки, написать лишние пробелы.

### Подсказки

1. Намек: "Станция читает не комментарий сверху, а строку в кавычках."
2. Направление: "Замени `DOCK CLOSED` на нужный сигнал."
3. Почти готовое решение: "Оставь кавычки и напиши внутри них `DOCK OPEN`."

### Награда и перенос навыка

- XP: 10
- Изменение мира: панель над дверью маяка меняет надпись.
- Открываемые темы: Java и JVM.
- Где навык повторится позже: строки в C02 и глубокая обработка текста в C08.

## Quest C01-Q03 — Дверь JVM

### Метаданные

- ID: C01-Q03
- Версия: 0.1.0
- Регион: Светлица
- Название: Дверь JVM
- Главная тема: Java и JVM на уровне идеи
- Prerequisites: C01-Q02
- Unlocks: C01-Q04
- Ориентир длительности: 6-8 минут
- Формат: объяснение + сортировка схемы

### Учебная цель

Игрок понимает базовую цепочку: исходный Java-код обрабатывается инструментами, превращается в байткод, а JVM выполняет байткод на станции.

### Проблема мира

Дверь учебной станции закрыта тремя плитами: `Source`, `Bytecode`, `JVM`. Они перепутаны, и станция не может объяснить новичку, где начинается выполнение.

### Диалог

Ира: "Мы не полезем в детали. Пока важно одно: станция не читает наши мысли. У нее есть путь от текста к выполнению."

Ника: "Если дверь просит схему, значит дверь хотя бы пытается быть педагогичной."

### Объяснение

- Простыми словами: Java-код сначала готовят инструменты, а выполняет его JVM.
- Аналогия: письмо переводят в формат, который понимают станции разных островов.
- Граница аналогии: байткод — не обычный человеческий перевод, а инструкции для виртуальной машины.
- Точная Java-модель: `javac` компилирует `.java` в `.class`, JVM выполняет байткод; на этом уровне не изучаем class loading и память.

### Пример

```text
Main.java -> Main.class -> JVM runs program
```

### Практика игрока

- Starter state: перепутанные карточки `JVM runs bytecode`, `Java source`, `bytecode`.
- Что разрешено менять: порядок карточек.
- Разрешенный API мира: нет.
- Что должно произойти после запуска: дверь станции открывается.

### Проверка

- Критерий успеха: схема упорядочена как source → bytecode → JVM.
- Допустимые варианты решения: подписи могут быть русскими или английскими, если смысл не искажен.
- Что проверять структурно: порядок концептов.
- Что не проверять поиском подстроки: не требовать знания `javac` как команды.
- Типичные ошибки: считать JVM компилятором исходного кода, считать байткод обычным Java-текстом.

### Подсказки

1. Намек: "Сначала есть текст, который пишет человек."
2. Направление: "JVM выполняет уже подготовленные инструкции."
3. Почти готовое решение: "Исходный код → байткод → JVM выполняет."

### Награда и перенос навыка

- XP: 10
- Изменение мира: открывается учебная станция Ядра.
- Открываемые темы: готовый `main`.
- Где навык повторится позже: C15, где JVM изучается глубоко.

## Quest C01-Q04 — Точка входа

### Метаданные

- ID: C01-Q04
- Версия: 0.1.0
- Регион: Светлица
- Название: Точка входа
- Главная тема: готовый `main`
- Prerequisites: C01-Q03
- Unlocks: C01-Q05
- Ориентир длительности: 7-10 минут
- Формат: квест в редакторе

### Учебная цель

Игрок узнает готовую оболочку `public class Main` и `public static void main(String[] args)` как место, откуда стартует программа, не углубляясь в модификаторы и ООП.

### Проблема мира

Станция открыта, но не знает, где начинать выполнение ремонтной инструкции. Нужно поместить действие внутрь готовой точки входа.

### Диалог

Ира: "Эта длинная строка выглядит страшнее, чем работает. Сейчас воспринимай ее как дверь: программа входит здесь."

Ника: "Подробности двери мы разберем позже. Не надо чинить замок, если нужно просто пройти."

### Объяснение

- Простыми словами: `main` — место старта программы.
- Аналогия: входная дверь мастерской, через которую начинается работа.
- Граница аналогии: `main` — не магия и не единственный метод в Java вообще; позже игрок узнает классы и методы.
- Точная Java-модель: JVM запускает метод `main` с ожидаемой сигнатурой; подробности `public`, `static`, `String[] args` откладываются.

### Пример

```java
public class Main {
    public static void main(String[] args) {
        // Команды программы будут здесь.
    }
}
```

### Практика игрока

- Starter code:

```java
public class Main {
    public static void main(String[] args) {
        // Put the signal command here.
    }
}
```

- Что разрешено менять: только тело `main`.
- Разрешенный API мира: пока нет явного API; игрок может вставить подготовленную строку-команду из UI.
- Что должно произойти после запуска: станция подсвечивает область `main` и принимает программу как запускаемую.

### Проверка

- Критерий успеха: рабочая команда находится внутри тела `main`, структура класса и метода сохранена.
- Допустимые варианты решения: команда может быть на любой строке внутри блока.
- Что проверять структурно: сохранены парные скобки, команда не вынесена за метод.
- Что не проверять поиском подстроки: не засчитывать команду в комментарии или вне `main`.
- Типичные ошибки: удалить закрывающую скобку, писать команду до `main`, менять сигнатуру.

### Подсказки

1. Намек: "Ищи фигурные скобки после `main`."
2. Направление: "Команда должна оказаться между `{` и `}` метода `main`."
3. Почти готовое решение: "Оставь оболочку как есть и добавь команду на строку с комментарием."

### Награда и перенос навыка

- XP: 30
- Изменение мира: терминал станции переходит из режима схемы в режим запуска.
- Открываемые темы: вывод через `System.out.println`.
- Где навык повторится позже: все ранние задачи C01-C06 используют готовый `main`.

## Quest C01-Q05 — Сигнал с берега

### Метаданные

- ID: C01-Q05
- Версия: 0.1.0
- Регион: Светлица
- Название: Сигнал с берега
- Главная тема: `System.out.println`
- Prerequisites: C01-Q04
- Unlocks: C01-Q06
- Ориентир длительности: 8-12 минут
- Формат: сюжетный квест

### Учебная цель

Игрок пишет строку вывода в готовом `main` и понимает, что stdout — это место, куда программа выводит текстовый результат.

### Проблема мира

Паром в тумане ждет подтверждения. Маяк может зажечь лампу только после того, как в журнале появится точная строка сигнала.

### Диалог

Ира: "Теперь маяк слушает программу. Напечатаем сигнал в журнал, и лампа поймет, что пора отвечать."

Капитан: "Я люблю поэзию, но сейчас мне нужна одна понятная строка."

### Объяснение

- Простыми словами: `System.out.println` выводит текст и переносит курсор на новую строку.
- Аналогия: записать сообщение в общий журнал станции.
- Граница аналогии: stdout — не обязательно экран игрока; в игре он отображается в панели результата.
- Точная Java-модель: `System.out.println("text");` вызывает метод вывода у стандартного потока.

### Пример

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("Hello, pier!");
    }
}
```

### Практика игрока

- Starter code:

```java
public class Main {
    public static void main(String[] args) {
        // Print the pier signal here.
    }
}
```

- Что разрешено менять: тело `main`.
- Разрешенный API мира: только stdout; прямые команды мира еще не вводятся.
- Что должно произойти после запуска: stdout содержит `LIGHTHOUSE READY`.

### Проверка

- Критерий успеха: программа выводит строку `LIGHTHOUSE READY`.
- Допустимые варианты решения: один или несколько `println`, если итоговый stdout содержит отдельную строку `LIGHTHOUSE READY` без искажения.
- Что проверять структурно: выражение находится в `main`, строка реально выводится.
- Что не проверять поиском подстроки: не засчитывать текст в комментарии или неисполняемой области.
- Типичные ошибки: забыть `;`, забыть кавычки, написать `System.out.printIn` с буквой `I` вместо `l`, вывести лишний текст в той же строке.

### Подсказки

1. Намек: "Нужная команда начинается с `System.out`."
2. Направление: "Текст сигнала должен быть в кавычках внутри `println`."
3. Почти готовое решение: `System.out.println("LIGHTHOUSE READY");`

### Награда и перенос навыка

- XP: 30
- Изменение мира: сигнальная лампа на причале загорается.
- Открываемые темы: комментарии и чтение старого журнала.
- Где навык повторится позже: отладочный вывод в ранних уроках, logging как более зрелая замена в C16.

## Quest C01-Q06 — Заметки смотрителя

### Метаданные

- ID: C01-Q06
- Версия: 0.1.0
- Регион: Светлица
- Название: Заметки смотрителя
- Главная тема: комментарии
- Prerequisites: C01-Q05
- Unlocks: C02-Q01 или вход в регион C02
- Ориентир длительности: 8-12 минут
- Формат: debugging-практика + финал главы

### Учебная цель

Игрок отличает код от комментария, понимает, зачем комментарии нужны человеку, и видит, что машина их не выполняет.

### Проблема мира

Главный фонарь мигнул, но не держит стабильный сигнал. В журнале старого смотрителя есть правильная команда, но она закомментирована рядом с устаревшей рабочей строкой.

### Диалог

Ника: "Смотри: правильная мысль здесь есть. Просто для машины она сейчас записана как заметка на полях."

Ира: "Комментарии полезны. Но маяк не зажжется от хорошего намерения в комментарии."

### Объяснение

- Простыми словами: комментарии помогают людям читать код, но Java их не выполняет.
- Аналогия: пометка карандашом на инструкции.
- Граница аналогии: комментарий остается частью файла, но не частью выполняемой программы.
- Точная Java-модель: `//` комментирует строку, `/* */` комментирует блок; компилятор игнорирует комментарии.

### Пример

```java
public class Main {
    public static void main(String[] args) {
        // This line is a note, not a command.
        System.out.println("This line runs.");
    }
}
```

### Практика игрока

- Starter code:

```java
public class Main {
    public static void main(String[] args) {
        System.out.println("LIGHTHOUSE TEST");
        // System.out.println("LIGHTHOUSE READY");
    }
}
```

- Что разрешено менять: тело `main`.
- Разрешенный API мира: stdout.
- Что должно произойти после запуска: stdout содержит `LIGHTHOUSE READY` и не содержит `LIGHTHOUSE TEST`.

### Проверка

- Критерий успеха: правильный сигнал выполняется как код, тестовый сигнал не выводится.
- Допустимые варианты решения: удалить тестовую строку или закомментировать ее; раскомментировать или заново написать правильную строку.
- Что проверять структурно: активный вывод правильной строки, отсутствие активного вывода тестовой строки.
- Что не проверять поиском подстроки: не считать правильный сигнал успешным, если он остался только после `//`.
- Типичные ошибки: раскомментировать обе строки, изменить текст комментария, удалить часть `main`.

### Подсказки

1. Намек: "Строка после `//` сейчас не выполняется."
2. Направление: "Сделай правильный сигнал кодом, а тестовый сигнал убери из выполнения."
3. Почти готовое решение:

```java
System.out.println("LIGHTHOUSE READY");
// System.out.println("LIGHTHOUSE TEST");
```
